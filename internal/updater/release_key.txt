# The ed25519 public keys a release may be signed by: one base64 line each, and
# any one of them may verify. Blank lines and lines beginning with # are ignored.
#
# The daemon embeds this file (internal/updater/verify.go, go:embed) rather than
# fetching it. A key retrieved at update time from the same host that serves the
# release is not a second factor — it is the same factor twice, and anyone able
# to serve a malicious binary and a matching checksum can serve the key that
# vouches for both. Embedding means the trust decision was made when the operator
# installed this binary, before any attacker was involved.
#
# install.sh carries the same lines in its RELEASE_KEYS block, because it is
# fetched on its own and has no checkout to read this from. A key added to one
# and not the other is a release the daemon installs and the installer refuses,
# or the other way round.
#
# Rotation is additive:
#
#   1. crswd keygen                      -> a new pair
#   2. add the new public line here, and to install.sh, keeping the old one
#   3. replace the RELEASE_SIGNING_KEY repository secret
#   4. wait until every retained release is signed by the new key
#   5. only then delete the old line
#
# Step 5 is the whole procedure. A rotation that deletes first strands every
# release an operator might need to roll back to.
#
# ---------------------------------------------------------------------------
#
# There are no keys here yet, and that is a halt rather than an omission. Until
# a line is added below, the daemon and install.sh refuse every release: an
# unsigned or unverifiable release is refused, never skipped (FR-025).
#
# Only the operator may add one. `crswd keygen` prints the line that goes here
# and writes nothing to disk; the private half goes into the repository secret
# RELEASE_SIGNING_KEY and nowhere else. A pair generated by anything other than
# the person who is supposed to hold it proves nothing about who signed a
# release, which is the entire property signing exists to buy.
