## ⛔ One task stops and waits for a human

**T013 must not be finished by the loop, and has not been.** It implements `crswd
keygen` and commits an **empty** `release_key.txt`, then **stops**. Both are done
and committed (Iteration 14); it is marked `- [!]` at the halt.

The loop must not generate a key, must not put one in a fixture, must not invent an
"example" key that happens to be valid, and must not proceed to sign anything.

The reason is the whole point of signing: the person who can produce a signature
must be the person who is supposed to. A key generated by an autonomous loop and
left in a transcript is not that person's key.

## 🔒 Four tasks are security-critical, in this order of risk

| Task | Why |
|---|---|
| **T015** verify | Checksum **then** signature, and a missing signature is a refusal, not a skip. Get this wrong and signing is decorative. |
| **T016** stage | Nothing executable before both checks pass; staging swept at startup. |
| **T017** swap | Smoke test before the rename; any failure leaves the daemon on what it was running. |
| **T013** keygen | Writes nothing to disk. The operator holds the private half. |

## ⚠️ The verification obligation

**Everything about the installer is about a machine this one is not.** Here the
project is already installed, a config exists, `~/.local/bin` is on `PATH`, and the
unit is in place — every precondition the installer creates is already true, so a
green run here proves nothing.

Where a task below carries the failing condition *"it was only ever run where the
project is already installed"*, that phrasing is the point and must not be softened.
**T012 is not optional polish**: without it, T009–T011 are proven only in the one
environment where they cannot fail.

## Phase 3: US3 — Install in one line (P3)

**Decomposed into four.** Every task here is about another machine.

- [x] T009 [US3] Create `install.sh` at the repository root: detect OS and architecture and refuse anything not published, naming what is; download the tarball, `SHA256SUMS` and `SHA256SUMS.sig`; **verify both before anything is made executable**. It must contain no personal name and no `/home/<user>` path. Tests in `internal/release/install_test.go`: `TestInstallVerifiesBeforeExecutable`, `TestInstallRefusesUnknownPlatform`, `TestInstallerNamesNobody`, `TestAssetNamesAgreeAcrossLanguages` (read the name built by `install.sh` and the Go constant and assert they agree). **Must fail when** they drift — a drift is a 404 at the exact moment somebody is installing.

- [x] T010 [US3] Place files in `install.sh`: binary to `~/.local/bin/crswd`; unit to `~/.config/systemd/user/crswd.service`; record the unit's hash at `~/.local/share/crswd/crswd.service.sha256`; write `~/.config/crswd/config` from the example **only if absent**, mode `0600`; print next steps naming the secret, the roots and the enable command; and **do not enable or start anything**. Tests: `TestConfigModeIs0600`, `TestInstallPrintsNextSteps`. **Must fail when** the config inherits umask, so a group-readable file holds a secret; or when convenience wins and a broken service starts on first boot.

- [x] T011 [US3] Add the clobber refusal to `install.sh`, comparing the installed unit against the hash recorded at T010: matching → replace; differing → **leave it and say so**; **no record → leave it and say so**. Tests: `TestInstallNeverOverwritesConfig`, `TestInstallNeverOverwritesEditedUnit`, `TestInstallLeavesNoRecordAlone`. **Must fail when** absence of a record is read as permission — that third case is every host deployed before this milestone, including the operator's own.

- [!] T012 [US3] **[BLOCKED behind T013/T014 — see `ralph/PROGRESS.md`, Iteration 12]** Add a `verify-install` job to `.github/workflows/release.yml` on **`ubuntu-latest`** — GitHub-hosted, **not** the self-hosted runners, which are this operator's machines and carry his home directory. It runs after the release, against **the published release**, with a fresh `HOME`, and runs the installer **twice**: once to prove it installs, once (after editing the config and unit) to prove it does not overwrite. It asserts `systemctl --user is-active crswd` reports `inactive`. **Must fail when** the installer is only ever run where the project is already installed — a green run on the author's machine proves nothing, because every precondition the installer creates is already true there.

## Phase 4: The signing key — ⛔ STOPS FOR A HUMAN

- [!] T013 🔒 **[SECURITY]** **[BUILT AND HALTED — see `ralph/PROGRESS.md`, Iteration 14. The
      command and the empty `release_key.txt` are committed; the key itself is the operator's
      step and the loop must not take it.]** Implement `crswd keygen` in new file `cmd/crswd/keygen.go`: generate an ed25519 pair, print **both halves to stdout** with instructions, and **write nothing to disk and log nothing**. Create `internal/updater/release_key.txt` **empty except for a comment** explaining the format (one base64 public key per line, rotation is additive). Tests in `cmd/crswd/keygen_test.go`: `TestKeygenWritesNothingToDisk`, `TestKeygenOutputIsParseableByVerifier`, `TestNoPrivateKeyInRepository`. **Then STOP**: mark this task `- [!]` in the plan and write into `PROGRESS.md` that the operator must (1) run `crswd keygen`, (2) add the private half as the repository secret `RELEASE_SIGNING_KEY`, (3) commit the public line to `release_key.txt`. **The loop must not generate a key, must not commit one, and must not proceed to T014.** **Must fail when** keygen "helpfully" saves the key to a file, which is how it ends up committed.

- [ ] T014 [US4] Sign `SHA256SUMS` in `.github/workflows/release.yml` using `RELEASE_SIGNING_KEY`, producing `SHA256SUMS.sig`. **Depends on T013's human step being done.** Test `TestReleaseIsSigned`. **Must fail when** a release publishes without a signature — the updater must then refuse it, so an unsigned release is a release nobody can install.

## Phase 5: US4 — Update without rebuilding (P4)

**Decomposed into five.** Depends on US1 twice: to know what to install, and for the smoke test.

- [ ] T015 🔒 **[SECURITY]** [US4] Create `internal/updater/verify.go`: sha256 of the downloaded bytes against `SHA256SUMS`, **then** `ed25519.Verify` of `SHA256SUMS.sig` against the keys in `internal/updater/release_key.txt`, embedded with `go:embed`. Any line may match (rotation is additive). Tests in `internal/updater/verify_test.go`: `TestChecksumMismatchRefuses`, `TestSignatureMismatchRefuses`, `TestUnsignedReleaseRefuses`, `TestVerifyAcceptsAnyCommittedKey`, `TestVerifyRejectsUnknownKey`, `TestReleaseKeyFileIsEmbedded`. **Must fail when** only the checksum is checked — that is the failure that makes signing decorative — or when a missing `.sig` reads as "nothing to verify against" rather than as a refusal.

- [ ] T016 🔒 **[SECURITY]** [US4] Create `internal/updater/stage.go`: download to `~/.local/share/crswd/staging/crswd.<version>` at mode **`0600`**, chmod to `0700` **only after** T015's verification passes, remove the staged file on any failure, and **sweep the staging directory at startup**. Tests in `internal/updater/stage_test.go`: `TestStagedFileIsNotExecutableBeforeVerification`, `TestFailedUpdateLeavesNothingExecutable`, `TestStagingSweptAtStartup`. **Must fail when** anything is chmod'd executable before the signature verifies, or a staged file is trusted across a restart — the process that vouched for those bytes did not live to say so.

- [ ] T017 🔒 **[SECURITY]** [US4] Create `internal/updater/swap.go`: exec the staged binary with `--version` and require it to print **exactly** the expected version; only then `os.Rename` over `~/.local/bin/crswd`, keeping the previous at `~/.local/bin/crswd.previous`; then exit 0 for systemd to restart. Tests in `internal/updater/swap_test.go`: `TestSmokeTestCatchesWrongArchitecture`, `TestSmokeTestRequiresMatchingVersion`, `TestPreviousBinaryKept`. **Must fail when** the smoke test is skipped — a cryptographically perfect wrong-architecture binary then becomes the installed one, which is an outage rather than a refusal — or when it checks only exit status, so any runnable file passes.

- [ ] T018 [US4] Create `internal/updater/fetch.go`: TLS to the GitHub API, an HTTP client that **refuses a redirect whose host differs** from the expected one, and asset matching by **exact name** rather than by suffix. Tests in `internal/updater/fetch_test.go`: `TestCrossHostRedirectRefused`, `TestAssetMatchedByExactName`. **Must fail when** the default client is used, which follows redirects anywhere.

- [ ] T019 🔒 **[SECURITY]** [US4] Add `POST /dashboard/update` in new file `internal/httpapi/update.go`, registered with `s.handleAction(...)` — **the same call destroy uses**, so the cross-site gate, the audit record and the ownership check are inherited rather than re-implemented. Form field `confirm` must equal `yes` (reuse `fieldConfirm`/`confirmYes`); optional field `version` names a release, absent means latest. Audit action `dashboard.update`. Tests in `internal/httpapi/update_test.go`: `TestUpdateRequiresConfirm`, `TestUpdateCrossSiteBothHalves`, `TestUpdateEmitsExactlyOneAuditRecord`, `TestNoKeyMaterialInAnyOutput`. **Must fail when** a test **disables** either cross-site half instead of satisfying it (AR-005), or when the route is registered by hand and the gate is re-implemented differently here.

## Dependencies

```
T001 (buildinfo) ──┬──> T002 (--version) ──────┐
                   └──> T003 (route)           │
                                               ▼
T004..T008 (release) ──> T009..T012 (installer)
        │
        └──> T013 [HUMAN] ──> T014 (sign)
                                  │
T001 ─────────────────────────────┴──> T015 → T016 → T017 (needs --version) → T019
                                             T018 ──────────────────────────┘
```

**US4 cannot start before US1**, and T017's smoke test is the second reason: it
execs the staged binary and checks what it prints.

**T014 and everything after it wait on a human.** The loop should take T020 and
T021 rather than idle.

## Parallel opportunities

- T003 alongside T002.
- T020 and T021 alongside anything — marked `[P]`.
- T018 alongside T015/T016; it is a different file and adds no verification.

## MVP scope

**US1 and US2 together are the shippable core.** A daemon that can say what it is,
and a release someone could download by hand. The installer and self-update are
what make it pleasant; releases are what make it possible.

## Anti-requirements

- **AR-005: a test satisfies the cross-site checks, it never disables them.**
- **AR-008: no refactoring outside the task's named files.**
- **A task is not done when the code exists. It is done when something calls it.**
  Five instances so far. **T015 is where it bites this time**: a verifier nothing
  calls is a release nothing checks.
- **Never generate, commit, or fixture a signing key.** T013 stops; it does not
  improvise.

## The gate, every task

```bash
go build ./... && go vet ./... && go test ./... && golangci-lint run
```

Plus `-tags tmux` and `-tags quickstart` where touched (T002, T012). All three
suites run in CI (#87). **Check the linter prints 2.12.2** — a pre-v2 binary reads
this repository's v2 config, runs zero linters, and exits 0.
